# Flare: Motion and sound

Version 1.0, Sat 2026-10-10. Owner: Motion and sound. Built in the prototype (design/prototype), with scripts in design/motion/.

Everything here is live in the prototype. Try it at `/lab/motion/` (every interaction), `/lab/fps/` (flame frame rate) and `/lab/haptics/` (haptics and sound), plus the clickable `/proto/`.

## 1. Principles and tokens

### Principles

1. **Motion says what changed.** Every animation maps to a state change a person cares about: a yes landed, it caught, it got smaller, it ended. Nothing moves for decoration alone.
2. **Shape first, then color, then motion.** A still frame of any state must read on its own (brand book section 2, the four states). Motion adds life; it never carries meaning alone.
3. **Short and calm.** UI responses take 90 to 260 ms. State changes take 480 ms. Only the photo (2.4 s) and the smoke (900 ms) run longer, because they cover real waits.
4. **One celebration.** Lit is the only moment with sparks, a pulse, a sound and a haptic together. Everything else is quieter.
5. **The phone goes back in the pocket.** No loops that beg for attention. The flame flickers gently; Gone stops moving after its drift.
6. **Reduced motion is a full design, not an off switch.** Every moment has a no-movement version that still shows the change (section 4).
7. **Sound and haptics are optional extras.** Each one always comes with a visual change. Muted, silent or haptic-less phones lose nothing.

### Tokens

Generated by `node design/system/build-tokens.mjs` into design/system/tokens.css and tokens.json (section `motion`). JS reads the same JSON through `src/lib/motion/core.ts`, so CSS and the shader share one source.

| Token | Value | Use |
| --- | --- | --- |
| `--dur-instant` | 90 ms | Button press down |
| `--dur-quick` | 160 ms | Button release, gold dot lights, sheet exit, color changes |
| `--dur-base` | 260 ms | Kindling step, count tick, sheet enter, word rise |
| `--dur-slow` | 480 ms | Lit catch, Ember settle, compass lock ring |
| `--dur-drift` | 900 ms | Gone smoke drift |
| `--dur-develop` | 2400 ms | Photo develop |
| `--dur-page` | 240 ms | Page and step transitions (new view) |
| `--dur-word` | 220 ms | Gap between the six words |
| `--dur-breathe` | 1800 ms | Compass facing glow, one breath |
| `--dur-flicker` | 2600 ms | CSS flame flicker loop |
| `--dur-fade` | 160 ms | Crossfade; the only duration kept under reduced motion |
| `--ease-out` | cubic-bezier(0.2, 0.8, 0.2, 1) | Default for things arriving |
| `--ease-in` | cubic-bezier(0.4, 0, 1, 1) | Things leaving (sheet exit, page out) |
| `--ease-in-out` | cubic-bezier(0.6, 0, 0.3, 1) | Loops, the develop |
| `--ease-spring` | cubic-bezier(0.34, 1.56, 0.64, 1) | Growth with overshoot: peak 9.8% past the target at 57% of the time |
| `--ease-settle` | cubic-bezier(0.3, 1.25, 0.5, 1) | Ember landing: peak 2.0% overshoot at 64% |
| `--ease-linear` | linear | Opacity-only fades |
| `--spring-sheet` | stiffness 420, damping 36: settles in 248 ms, 0% overshoot | Sheet snap-back after a drag |
| `--spring-needle` | stiffness 180, damping 22: settles in 532 ms, 1.1% overshoot | Compass needle following the bearing |

Springs are emitted as CSS `linear()` curves (sampled at 25 points, settle = last time the curve is more than 0.5% from its target) plus `--spring-*-dur`. Browsers without `linear()` fall back to the default `ease` curve, which is fine for both uses.

Reduced motion: `@media (prefers-reduced-motion: reduce)` and any `[data-reduce-motion]` ancestor set every `--dur-*` and `--spring-*-dur` to 0 ms except `--dur-fade`. The prototype also has an in-app setting: `localStorage["flare.motion"] = "reduce"` puts `data-reduce-motion` on `<html>` (root layout).

## 2. The flame

### Decision

**WebGL shader, CSS/SVG fallback: the lab's call is confirmed, but the shader is redrawn on the brand silhouette.** The lab's shader (lab/reports/06-flame.md) builds a generic teardrop out of noise. It has no hole and is not our mark, and the brand rule is "never fill" the hole and never move or resize it (brand book section 1). Ours keeps the exact paths from `src/lib/brand.ts`:

- At first use, a 2D canvas draws FLAME (with HOLE), DOME (with its ring) and the Gone mark into the red, green and blue channels of one 512 × 512 mask texture. A 128 px blurred copy of the flame becomes the alpha channel (glow and the inner tongue).
- The fragment shader (`src/lib/motion/flame-shader.ts`, 2,032 bytes of GLSL, GLSL ES 1.00 so it runs on WebGL 1 and 2) samples that mask. Two noise fields bend only the part above the hole, so the hole stays round and still. The bend grows toward the tip.
- A lighter inner tongue is the same silhouette at 50% size, cut off below the hole and mixed 45% toward gold-400.
- Lit lights the gold dot in the hole. Ember is the dome with a slow 3.2 s glow. Gone is the dashed ring and smoke that sways with height.
- Edges are cut at 0.5 coverage with a softness of about one device pixel, so the shape is sharp at any size. The canvas covers 140% of the flame box so the glow and the smoke have room.
- Colors come from the CSS role variables (`--kindling`, `--lit`, `--ember`, `--gone`, `--c-gold-400`) at each state change, so light, dark and sun mode all work.

Beat or confirm, in numbers (same M4 laptop and Chrome 154 as the lab):

| | Lab shader | Flare shader |
| --- | --- | --- |
| Silhouette | Generic noise teardrop, no hole | Brand pin-flame, hole kept, four brand states |
| Shipped bytes, brotli | 1.9 KB (page and script) | 954 B of GLSL; 3.6 KB for the whole lazy chunk (shader, renderer, mask builder, tweens) |
| Canvas at DPR 2 | 320 × 400 px (128,000) | 560 × 560 px (313,600) for a 200 px flame |
| Main thread, 1x | 2.3% | 3.2% (includes the page's own fps meter) |
| GPU process CPU, 1x | 10.8% | 6.2% |
| Frames, 1x, 4x, 6x | 60 fps, 0 dropped | 60 fps, 0 dropped |

So: same frame rate, 2.45 times the pixels for 43% less GPU-process CPU, and the real mark. It costs about 1.7 KB more brotli than the lab page because it builds the brand mask at runtime. The methods differ a little (the lab's test page vs our /lab/fps page), so read the comparison as rough.

### When the shader runs (capability detection)

`Flame.svelte` always renders the SVG first (server render, first paint, exports, screen readers). It then starts the shader only if all of these hold:

1. `animate` is on and `mode` is not `css`;
2. reduced motion is off: no `prefers-reduced-motion: reduce`, no `[data-reduce-motion]` on the flame or the page (it re-checks when the OS setting changes);
3. the flame is 72 px or larger (smaller flames, such as list rows and the 24 px marks, stay SVG);
4. `?flame=css` or `html[data-flame="css"]` is not set (manual override for testing);
5. a WebGL 2 or WebGL 1 context opens and the shader compiles (tested once per page);
6. fewer than 4 shader flames are live on the page (browsers cap WebGL contexts; Chrome allows 16, and we stay well under for iOS).

Once running, it fades in over the SVG in 160 ms. It also:

- pauses when the flame scrolls off screen (IntersectionObserver) or the tab is hidden;
- auto-downgrades: if more than 10% of frames in a 2 s window arrive 1.5 times later than the best median, the pixel ratio drops from 2 to 1; if it is still late, the flame switches to the CSS version. This uses relative lateness, so Low Power Mode's steady 30 fps (WebKit bug 215745) does not trigger it;
- falls back to CSS on WebGL context loss.

The CSS/SVG flame animates only `transform` and `opacity`, never `filter: blur` (a known iOS Safari slow path, WebKit bug 228312).

## 3. Micro-interactions

Times are from the moment of the trigger. "Shader" means the WebGL flame (`src/lib/motion/flame-gl.ts`, `setState`); "CSS" means the SVG fallback (`Flame.svelte`). Both follow the same spec. Sound and haptics come from one call, `feedback(moment)` in `src/lib/motion/feedback.ts`.

### 3.4 The photo develops, then the six words

**Decision: the develop never waits on the hub.** The photo is already on the phone. Holding it back for the network would make the camera feel broken. The develop is a fixed 2.4 s, and the lab measured the hub at about 3.0 s, so it covers most of the wait. The words follow the hub.

| Layer (all opacity only) | 0% | Timing within 2,400 ms |
| --- | --- | --- |
| Image | 0 to 1 | 0 to 70%, `--ease-in-out` |
| Paper haze (birch-50) | 0.85 to 0 | 0 to 60%, `--ease-out` |
| Sepia veil (multiply) | 0.9 to 0 | 20 to 85% |
| Edge vignette (multiply) | 1 to 0 | 45 to 100%: the edges clear last, the "chemical edge" |

- **No flash.** The brand is calm, and a flash adds nothing the edge doesn't.
- **No `filter: blur`.** The old version animated blur and sepia filters; filters are a known iOS Safari slow path.
- **Words:** they start when the draft arrives, never before 1,440 ms (60% of the develop), so the photo leads. One word every 220 ms. Each rises 8 px with a fade over 260 ms on `--ease-spring`. Six words take 1,360 ms from the first to the last one settling. With the hub at 3.0 s, the words run from 3.0 to 4.4 s. Until then the line "Writing six words…" breathes (H2, unchanged).
- **Screen reader:** hears the full line once, when complete.
- **Reduced motion:** the finished print fades in over 160 ms; all six words appear at once.
- **Built in:** PhotoPrint.svelte, TypeWords.svelte (`delay` prop), H2, /lab/motion "Develop again".

### 3.5 The compass locks on (facing)

| | Spec |
| --- | --- |
| Needle | Follows the bearing on `--spring-needle` (532 ms, 1.1% overshoot). |
| Lock | Locks on below 15° and lets go only above 25°, so a shaky hand doesn't flicker it. |
| On lock | The gold dot in the pointer's hole scales from 30% to 100%, 160 ms `--ease-spring`. One gold ring goes out from 1 to 1.55 times its size and fades, 480 ms `--ease-out`. The glow fills to 30% gold in 260 ms, then breathes (opacity 1, 0.6, 1 over 1.8 s) from 480 ms. |

### 3.6 The Ember settles, 480 ms

- **Shader:** the flame sinks (height 100% to 45%, `--ease-out`) and fades as it reaches the dome (`--ease-in`). The dome lands from 1.6 times its height on `--ease-settle` (2% overshoot). Flicker 1 to 0.3; the dot goes out in 160 ms. Then the coal glows: center 55% toward the flame color, brightness ±7%, one breath per 3.2 s.
- **CSS:** the dome goes from scaleY 1.6 and 60% opacity to its shape, 480 ms `--ease-settle`.
- **Sound:** "ember", the soft low note, 700 ms. No haptic: nothing went wrong, it got smaller.
- **Reduced motion:** a 160 ms crossfade.
- **Built in:** flame-gl.ts, Flame.svelte, /proto "Shrinks to an Ember" (I9), /lab/motion "Ember".

### 3.7 The smoke when Gone, 900 ms

- **Shader:** the flame or dome fades in 260 ms. The Gone mark fades in over 160 ms and drifts from 4 units left and 6 units down to its place (up and right), 900 ms `--ease-out`. The smoke line sways gently with height for 1.5 s more. Then the shader keeps the last frame and stops drawing: Gone is still.
- **CSS:** the same drift, 900 ms, then still.
- **Sound and haptic:** silence, on purpose.
- **Reduced motion:** a 160 ms crossfade.
- **Built in:** flame-gl.ts, Flame.svelte, I10, P7, /lab/motion "Gone".

### 3.8 Sheet enter and exit

- **Enter:** rises 24 px with a fade, 260 ms `--ease-out`; the overlay fades in, 260 ms.
- **Exit:** drops 32 px with a fade, 160 ms `--ease-in`; the overlay fades out, 160 ms. Bits UI waits for the exit animation before it unmounts.
- **Drag to dismiss:** drag the handle (a 28 px tall strip over the grab bar). The sheet follows the finger 1:1, downward only. On release it closes past 30% of its height or faster than 0.6 px/ms. Otherwise it snaps back on `--spring-sheet` (248 ms, no overshoot). Escape and the close buttons work as before (focus trap, focus restore).
- **Reduced motion:** 160 ms fades only; no drag spring.
- **Built in:** Sheet.svelte, /lab/motion "Open sheet".

### 3.9 Button press

- **Down:** to 97% scale and 1 px lower in 90 ms `--ease-out`; the primary shadow drops from `--e-2` to `--e-1`.
- **Release:** back on `--ease-spring` in 160 ms.
- **Applies to:** every variant (primary, secondary, text, danger).
- **Reduced motion:** no scale; the primary button darkens to 90% brightness while pressed.
- **Haptic:** opt-in per button with `haptic="tap"` (Button.svelte), used for the yes.

### 3.10 Page transitions

- **With the View Transitions API** (`document.startViewTransition`, called from SvelteKit `onNavigate` in the root layout): the old page fades out and drops 8 px (160 ms `--ease-in`); the new page fades in and rises 12 px (240 ms `--ease-out`).
- **Prototype steps:** the same motion on the phone only (`view-transition-name: vt-phone`). The update waits for the next screen to load, so the new snapshot is complete (BUG-019).
- **Reduced motion:** the same API with a 160 ms crossfade and no movement.
- **No API** (Safari before 18 and other older browsers): the page swaps at once. Nothing waits and nothing breaks.
- **Built in:** `src/lib/motion/transitions.ts` and `transitions.css`, `src/routes/+layout.svelte`, /proto.
- **Checked:** `design/motion/check-vt.mjs` saw one `startViewTransition` call per navigation, `data-vt="page"` normally and `data-vt="fade"` with reduced motion, and 0 page errors.

## 5. Sound

All four sounds are original. They are synthesized from sine waves and seeded noise by `design/motion/make-sounds.mjs` (no samples, no third-party audio, so no license to cite). Running the script twice gives byte-identical WAV files (checked with md5). Gone is silent on purpose.

| Sound | Plays when | Recipe | Length | Peak dBFS | RMS dBFS | Loudest 50 ms RMS dBFS | Shipped file |
| --- | --- | --- | --- | --- | --- | --- | --- |
| yes | Your own yes-tap; the host's count rises | Band-passed noise snap at 3.2 kHz plus a 1.65 kHz wooden knock, 4 to 9 ms decays | 70 ms | -6.0 | -24.6 | -23.1 | yes.wav, 3,404 B |
| lit | It catches | Pitch drop 150 to 58 Hz with 2nd and 3rd harmonics, plus a 120 to 420 Hz noise breath | 520 ms | -3.0 | -16.6 | -9.1 | lit.m4a, 8,199 B (WAV 25,004 B fallback) |
| ember | It shrinks to an Ember | A3 220 Hz, a quiet octave and a 661 Hz partial, 40 ms attack | 700 ms | -9.0 | -21.6 | -14.6 | ember.m4a, 6,138 B (WAV 33,644 B fallback) |
| facing | The compass locks on and the phone can't vibrate | B5 988 Hz with a soft fifth, 35 ms decay | 140 ms | -10.0 | -23.0 | -18.8 | facing.wav, 6,764 B |

Levels are measured from the samples by the generator (`design/motion/sounds.json`). Format: 24 kHz, 16-bit, mono.

**Mixing:**

- Lit is the loudest moment: it is the celebration, -9.1 dBFS over its loudest 50 ms.
- The tick sits about 14 dB under it, because it can repeat.
- Ember is 5.5 dB under Lit, so it reads as calm news.
- The facing tone sits under speech so it never covers the spoken direction.
- Per-sound gain is 0.85 to 0.9 into a master gain of 0.8.
- Phone speakers carry little below about 300 Hz, so the whump's weight comes from its harmonics and the 250 Hz breath, not the 58 Hz fundamental.

**Format:** AAC (`afconvert`, 64 kbps) is shipped only where it is under 60% of the WAV. The two long sounds are 3 to 5 times smaller as M4A. The two short ones are bigger as M4A (4,725 and 4,693 B), so they stay WAV. In Chrome both formats decode with under 1.1 ms before the first sound sample (`design/motion/check-audio.mjs`). Total download is 24,505 bytes. It is fetched only after the first tap.

**Rules** (`src/lib/motion/sound.ts`):

1. **Never before a user gesture.** The root layout arms `startAudio()` for the first `pointerdown` or `keydown`. Inside that gesture it creates and resumes the `AudioContext` and plays one silent sample, which is how iOS lets a page start audio. Then it loads the files. Checked in Chrome: 0 AudioContexts before any tap, 1 after the first tap.
2. **The silent switch wins.** It sets `navigator.audioSession.type = "ambient"` where it exists (Safari 16.4+). WebKit engineers say ambient audio is muted by the ring/silent switch (WebKit bugs 237322 and 264473).
3. **The user's mute wins.** "Sound off" is remembered on the phone (`localStorage["flare.sound"] = "off"`): the "Sound" toggle in /proto, /lab/motion and /lab/haptics.
4. Nothing plays while the page is hidden. The same sound never plays twice within 120 ms.
5. Every sound has a visual twin, so a muted phone loses nothing.

**Open for the architect:** SRS-CMP-7 wants the compass to keep speaking with the screen locked. Speech uses `speechSynthesis`, not the Web Audio session, and whether it keeps going when the screen locks on iOS is unverified. Test it Sunday on /lab/motion with "Speak" on.

## 6. Haptics

### What the research says (Oct 10, 2026)

- **`navigator.vibrate`:** Chrome on Android supports it. No version of Safari does, desktop or iOS, and Firefox removed it in version 129 ([caniuse "Vibration API"](https://caniuse.com/vibration)). It needs sticky user activation ([MDN, Navigator.vibrate()](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/vibrate)).
- **`<input type="checkbox" switch>`:** shipped in Safari 17.4 ([WebKit, "WebKit Features in Safari 17.4", 2024-03-05](https://webkit.org/blog/15063/)). Toggling it with a real tap plays the system haptic on iPhone. This is the basis of every web haptics library for iOS ([azukiazusa, "iOS Safari web haptics", 2026-03-04](https://azukiazusa.dev/en/blog/ios-safari-web-haptics)).
- **iOS 17.4 to 26.4:** a script `label.click()` on a hidden switch also fired the haptic, even with `display:none` ([ios-haptics docs, "How it works"](https://mintlify.wiki/tijnjh/ios-haptics/guides/how-it-works)).
- **iOS 26.5 and later:** programmatic clicks reach the switch as untrusted, so no haptic, even inside a tap handler. Sources: the [ios-haptics 3.1.1 README by tijnjh](https://github.com/tijnjh/ios-haptics) and [mxerf/tappt PR #5 (2026-09-25)](https://github.com/mxerf/tappt/pull/5), which cites WebKit commit fc1ef83, bug 309082. The bug is access-restricted, so this is not confirmed from Apple.
- **What still works on 26.5+:** a transparent `<label>` for a hidden switch laid over the control, so the user's own finger toggles it. You get one tick per tap; patterns don't work ([Kushagra Golash, haptics-web](https://haptics-web.vercel.app/), tappt PR #5).
- **System setting:** a port's docs say the switch haptic needs System Haptics on, in Settings, Sounds & Haptics ([web_haptics on pub.dev](https://pub.dev/documentation/web_haptics/latest/)). This is likely but not tested by us.
- **Apple's guidance** ([HIG, Playing haptics](https://developer.apple.com/design/human-interface-guidelines/playing-haptics)): "Avoid overusing haptics." Use them consistently, to complement other feedback, and make them optional.
- **DEV posts found** (not read in full): ["Adding native-feeling haptics to Angular web apps with ng-haptics" (xaconi_94)](https://dev.to/xaconi_94/adding-native-feeling-haptics-to-angular-web-apps-with-ng-haptics-3j3l) and ["Beyond Visual: Why We Should Be Using More Haptic Feedback on the Web" (luxonauta)](https://dev.to/luxonauta/beyond-visual-why-we-should-be-using-more-haptic-feedback-on-the-web-1adg). Neither covers the 26.5 change.

### What we built (`src/lib/motion/haptics.ts`)

| Path | Where | When |
| --- | --- | --- |
| `hapticTap` action / `<Button haptic="tap">` | Safari with switch support | Lays a transparent label over the button. The finger's own tap toggles a hidden switch: one system tick. The button's click still runs once; the switch's own click is stopped so it can't run twice. Added only at runtime in Safari, so desktop axe runs never see it. |
| `haptic(kind)` with `navigator.vibrate` | Android Chrome | `tap` 12 ms, `success` [18, 70, 28] ms, `facing` 10 ms, only after the page has had a user gesture |
| `haptic(kind)` with a script click on a hidden switch | Safari, inside a tap only (`navigator.userActivation.isActive`) | Reported to work on iOS 17.4 to 26.4 only; harmless on 26.5+ |
| none | Everything else | Callers always pair the haptic with a sound or a visual change |

**Rules:**

1. Haptics are feedback for a real user action (the yes) or a state the user is actively watching (facing). Never for marketing, never on page load, never in a loop.
2. At most one haptic per 400 ms.
3. The compass tick fires at most once per 3 s.
4. Off when the user turns haptics off in Flare (`localStorage["flare.haptics"] = "off"`).
5. Lit by someone else gives no haptic on iOS, because there is no tap; the whump and the sparks carry it.

**Verified:** in desktop Chrome, `navigator.vibrate` exists (this Mac has no motor), switch support is "no", and no overlay is added. **Not verified:** any haptic on any iPhone. The `/lab/haptics/` page tests all four paths and asks the person holding the phone to answer "Felt it" or "Nothing", because code can't detect a haptic.
