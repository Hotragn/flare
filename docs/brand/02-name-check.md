## Risk

| Area | Risk | Why |
| --- | --- | --- |
| This weekend (open-source web app, DEV post, no store listing) | **Medium** | A real, active, well-rated app named Flare does group events. Judges won't confuse them, but a reader searching "Flare app" finds them first. |
| An App Store listing named "Flare" | **High** | Same category and job as "Flare - For Groups". Likely trademark conflict. |
| npm or GitHub naming | **Low** | Crowded but unrelated; use a distinct package and repo name. |

## Decisions and recommendation

1. **Keep "Flare" as the product name for this weekend.** The brand system is built around fire states; the name is short and memorable; the risk this weekend is confusion, not exclusion.
2. **Always pair it with a descriptor in public** where the name stands alone: "Flare, for getting friends outside" on the site title, OG image and post title area. Never "Flare app" alone.
3. **Package and repo names:** use `flare-outside` (free on npm). The private GitHub repo can stay `flare`; if made public, `flare-outside` avoids search collisions. (Founder's call; renaming a repo needs their yes when public.)
4. **Before any store listing or commercial use:** run a USPTO and EUIPO trademark search and get legal advice. If the conflict holds, the fire-state system survives a rename; keep the mark and rename the word.
